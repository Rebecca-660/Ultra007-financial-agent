## 一 继续使用现有后端

保留 FinancialOrchestratorAgent、ReportEvidenceAgent、HistoricalMetricsAgent 三个 Agent，以及 `FinancialAnalysisAgent` 的 prepare、finalize、status、ask 接口。界面调用这些接口，不在页面里重写财务计算，也不另建一套 Excel 生成流程。

本次用户已明确确认全部 12 张表通过，比较差异采用各年原报本年数。程序代录保存用户原话、审核范围、数据指纹、审核人归属和时间；这不是 Agent 自动批准。以后换报告或重新提取后，必须重新确认新版本。

## 二 Week7 中借鉴的设计

参考材料为 `Week7/AI and Finance - Week7.pdf`、`Week7/multi_agent_finance_demo(1).py`、`Week7/streamlit_app.py`。它们作为课堂设计参考，不覆盖本项目需求。

| 课堂设计 | 在本项目中应用 |
|---|---|
| 顶部到末尾重跑的执行方式 | 页面重新绘制不自动重复 prepare/finalize，分析必须由按钮触发 |
| `st.session_state` 保留结果 | 保存当前公司、报告集合、run_dir、筛选状态和最近结果摘要 |
| `st.cache_data` 缓存数据 | 缓存只读分析结果，键包含路径、文件版本与数据指纹 |
| `st.cache_resource` 缓存昂贵对象 | 优先缓存只读模型资源；共享索引必须按报告集合和版本隔离 |
| 工具事件与进度条 | 展示实际取证、提取、来源复核、计算和导出事件；阶段进度不冒充真实耗时百分比 |
| sidebar、columns、expander | 侧栏选运行和年度，主体看指标与图表，展开查看公式、来源和限制 |
| Pydantic 校验保存状态 | 页面恢复时检查 schema、候选指纹与运行状态，拒绝复用过期审核 |

不照搬示例的固定 2024 年、三个固定公司、默认 USD millions、固定阈值或另一个 ReviewAgent。课堂 ReviewAgent 的文字检查不能替代本项目人工批准。示例导入名与附件文件名也不一致，本项目页面应导入自己的 service 模块。

可变 Agent、异步锁和用户审核状态不放入跨用户共享的全局缓存；同一 Agent 实例不在不同事件循环之间反复复用。首版面向本机单用户演示，多用户部署需要额外的访问隔离与任务管理。

## 三 分阶段实施

### 阶段 A 先做正式结果展示

状态：已实现。入口 `streamlit_app.py`，本机启动和使用步骤见 `Streamlit_运行说明.md`，验证记录见 `data/validation/streamlit_stage_a/验收记录.md`。

先读取已有 completed 运行，不在首次打开页面时启动模型。

页面包含：运行选择、公司与年度、关键收入和利润、同比、盈利能力、资产负债率、流动性、现金流；展示指标表、五类趋势图、缺失原因和 Excel 下载。表格能按年度和指标类别筛选，金额与百分比清楚区分。

数据直接读取 `analysis.json`，使用已有公式、输入来源与不可计算原因。显示单位并保留精度；缺失数据留空并解释，不能转成零。来源可定位到原报告和 PDF 物理页。

完成条件：改变筛选不调用模型；刷新后仍能按 run_dir 找回结果；下载文件与该次 completed 运行一致。

### 阶段 B 接入上传和候选提取

增加多份文本型 PDF 上传，用户确认同一公司、各报告年度和重复版本选择，生成报告清单后调用 prepare。界面展示真实进度事件、失败原因、候选表和待审核 Excel 下载。

每次按钮操作绑定独立 run_dir；运行中限制重复提交。换公司或文件内容改变，旧运行和旧审核不会自动进入新分析。

完成条件：用户不操作命令行就能从上传走到候选工作簿；切换控件、刷新或重复点击不会无意启动第二个付费任务。

### 阶段 C 把人工审核接入页面

提供原表只读区和独立修正区，保留行标识、列标识、原值、修正理由。支持逐表批准、拒绝、审核人和比较差异处理；可以先沿用上传已填写审核 Excel，再实现网页审核编辑器。

网页提交时把审核内容转换为已有 Review 数据结构，复用当前来源验证和计算拦截。只有明确的用户提交才能形成批准记录；来源或候选改变，页面必须要求重新审核。

完成条件：未完成审核无法生成正式分析；零修正、明确缺失、理由、审核归属和来源摘要都能正确保存，重开程序后仍可恢复。

### 阶段 D 完整流程与演示验收

页面调用 finalize，显示来源复核、确定性计算、导出状态，完成后自动展示同一运行的结果。支持恢复失败任务和查看历史运行，避免覆盖已有输出。

增加用户可理解的错误提示；界面和可下载日志不暴露 `.env`、密钥或供应商请求头。长任务通过受控任务或队列交给后台，Streamlit 主线程负责展示；前端刷新不丢失落盘任务。

完成条件：上传 → 候选 → 审核 → 分析 → 图表 → Excel 下载在页面走通；覆盖重跑、重复提交、切换报告、旧版本状态、缺失指标、失败恢复及来源变化。
