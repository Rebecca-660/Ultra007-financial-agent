# 财报研究后端架构与运行说明

2026年10月28日更新。当前按“先完成后端，再接入 App”的顺序实施。新增代码没有修改 `streamlit_app.py`，现有展示页继续使用原来的正式结果。新流程通过 Python 服务和命令行运行。

## 本轮功能与实现状态

| 用户需要的能力 | 当前实现 |
|---|---|
| 单份年报 | 复用完整合并三表、人工审核、固定历史指标、Excel 和五类原生图表；单年无跨年 CAGR，不补造趋势 |
| 同公司多年年报 | 保留原有纵向分析、同比和连续年度 CAGR，年度数据按用户确认口径处理 |
| 多公司报告及自选比较对象 | 新研究任务按公司隔离来源与运行，用户显式选择公司；比较共同年度，输出数据、趋势图、收入指数和样本中位数 |
| 历史分析后询问是否继续 | 生成绑定当前数据版本的邀请，命令行 `interact` 提问，也可由服务返回结构化问题供未来页面显示 |
| 用户不同意 | 保存 `declined`，结束参数收集；禁止读取参数文件或执行估值，历史结果保留 |
| 用户同意并提供参数 | 先保存继续的决定，再通过 JSON 或命令行逐项问答收集参数，用户再次确认参数后才计算 |
| FCFF DCF | 固定 Decimal 公式，支持直接 WACC 或组成项、Base/Bear/Bull、权益桥接、每股模型值、敏感性与条件性说明 |
| 上传接口 | 已有本地文件清单和 `create_from_uploads` 字节接口；本轮不做网页上传窗口 |
| 人工审核接口 | 原有 Excel 审核继续支持，新增结构化 JSON 提交和独立审核副本；本轮不做网页审核窗口 |

原有真实四年样例与本轮新增功能的验证分开记录。多公司与 DCF 的贯通验证使用明确标注的合成 PDF 和参数，不能作为真实公司估值。

## 数据流程

1. 用户确认每份 PDF 属于哪家公司和哪个报告年度，填写公司行业、会计准则、财年末和业务类型。
2. 接收文件并复制到独立研究项目；校验真实 PDF、文本层、重复文件、重复公司年度和文件大小。
3. `prepare` 对所选公司逐个复用原有三个 Agent，生成完整三表候选、待审核 Excel 和 JSON 审核模板。其他公司不受影响。
4. 用户对照原 PDF 填写审核；可提交 JSON，或沿用填写 Excel 的方式。未获批准、旧版本批准、比较差异未处理都不能进入正式分析。
5. `finalize` 复核原页并计算正式历史结果。`history` 按选择输出单公司结果或横向比较。
6. 用户收到继续估值的问题。选择停止后结束；选择继续后拿到没有预填经验参数的模板，或通过逐项问答填写。
7. 用户核对并确认完整参数；确定性代码计算 DCF，保存参数、指纹、详细现金流、公式、工作簿和条件性结论。

每次研究有独立项目目录，项目内每家公司有独立报告清单和运行。通过文件锁阻止同项目重复提交；已有候选默认恢复，不重新执行付费任务。已完成的分析和估值产物不覆盖。

## 运行前准备

在 Windows 命令提示符中进入项目：

```bat
cd /d "C:\Users\Lenovo\Desktop\AI&Finance\project"
python -m pip install -r requirements.txt
python run_finance.py research --help
```

沿用原 `.env` 和嵌入模型配置。只有候选提取和正式分析需要原有模型调用；比较、用户选择、参数校验、DCF 和工作簿导出不调用大模型。请不要把 `.env` 内容放入输入清单、参数文件或输出报告。

## 第一步 准备报告清单并建立研究

复制 `config/research.example.json` 为自己的清单。清单中的文件路径相对于该清单所在文件夹；Windows 路径在 JSON 中使用 `/` 或双反斜线。

填写实际公司资料与确认人，核对后将各公司的 `comparability_confirmed` 改为 `true`。示例默认空确认人和 `false`，避免把模板直接当成已确认资料。`financial` 表示银行、保险等金融企业，它们可以历史分析，但不能使用当前 FCFF 模型。

- 单份年报：只保留一家公司的一个报告条目。
- 同公司多年：保留该公司及其多个年度条目。
- 多公司：为每家公司指定不同 `company_id`，再填写其报告条目。
- 同公司同年度有多个版本：先选一个主版本，不自动覆盖。
- 需要特殊解析：在该公司的 `parser_profile` 指定配置路径，复用原来的版式和别名适配。

```bat
python run_finance.py research create --manifest config\my_research.json
```

记下输出的 `project_dir`。以下命令中的 `PROJECT` 请替换为这个实际路径，`company_a` 替换为实际公司标识。

```bat
python run_finance.py research status --project "PROJECT"
python run_finance.py research prepare --project "PROJECT"
```

也可只提取部分公司：

```bat
python run_finance.py research prepare --project "PROJECT" --companies company_a
```

运行状态内有每家公司的 `run_dir`，相对于项目目录。打开其中的 `待审核财务报表.xlsx`，对照原年报检查。`prepare` 本身不会批准任何报表。

## 第二步 提交人工审核并生成历史分析

可选择两种方式，任选其一。

**沿用 Excel 审核。** 在候选副本中填写“审核”页、审核人及比较差异处理；需要修正时使用独立黄色修正栏并写理由，不直接改原始值。保存后：

```bat
python run_finance.py research finalize --project "PROJECT" --company company_a --review "已填写审核.xlsx"
```

**使用结构化审核。** 将运行目录的 `human_review.template.json` 另存为自己的审核文件，填写：

- 顶层 `confirmed_by` 为审核人，`source_checked` 为 `true`，`statement` 写实际确认内容。
- 各项 `decision` 填 `approved` 或 `rejected`，`reviewer` 与提交人一致。
- 有跨报告差异并选择各年原报本年数时，填 `conflict_resolution: "as_reported"`。
- `statement_id`、`statement_digest`、`dataset_fingerprint` 和 `report_set_id` 不改。
- 金额修正放在对应决定的 `corrections` 中，包含 `row_id`、`column_id`、`original`、`corrected` 和非空 `reason`；零是有效数值，JSON `null` 表示修正为缺失。

```bat
python run_finance.py research review --project "PROJECT" --company company_a --submission "我的审核.json"
python run_finance.py research finalize --project "PROJECT" --company company_a
```

系统保存提交副本、结构化决策和已填写审核 Excel。全部报表批准后才能正式分析。新数据必须重新审核；其他公司的批准不能复用。拒绝的报表不进入计算。

## 第三步 选择历史分析范围

单公司：

```bat
python run_finance.py research history --project "PROJECT" --companies company_a
```

多公司，可只比较已上传公司中的一部分：

```bat
python run_finance.py research history --project "PROJECT" --companies company_a company_b
python run_finance.py research history --project "PROJECT" --companies company_a company_b --years 2024
```

默认共同报告年度；显式年度必须属于所有所选公司的交集。币种、会计准则与完整财年末不一致时拒绝比较。当前不自动换汇、拼接短财年或把不同报告年度并列排名。

横向结果保存于 `comparisons`，含比较 JSON、可比数据、四类趋势图、收入指数、样本统计和来源口径。收入指数以共同起始年为 100。同行业统计仅称“用户选择公司样本中位数”，记录有效样本数；跨行业不生成行业统计。缺失值不填零。

## 第四步 是否继续估值

命令行真实提问，用户可以回答 `yes` 或 `no`：

```bat
python run_finance.py research interact --project "PROJECT" --companies company_a --by "审核与判断人"
```

回答 `no`：保存停止决定，保留历史输出，不要求估值参数。再次调用估值也会被拦截。

回答 `yes`：保存继续决定并显示参数模板位置。模板中的经验参数为空，用户填写并确认后才可计算。继续的决定与参数确认是两次不同的操作。

也可不用终端提问，明确提交决定：

```bat
python run_finance.py research decide --project "PROJECT" --company company_a --choice stop --by "判断人"
python run_finance.py research decide --project "PROJECT" --company company_b --choice continue --by "判断人"
```

同一数据版本的决定不悄悄覆盖；决定保存后允许反复读取。选择停止的公司与选择继续的公司相互独立。

## 第五步 人工填写参数并计算 DCF

有两种填写方式。

**逐项问答。** 选择继续后，在命令行输入数值，末尾查看完整参数并输入 `CONFIRM` 才计算：

```bat
python run_finance.py research interact --project "PROJECT" --companies company_b --by "判断人" --collect
```

**填写 JSON。** 将邀请目录中的 `assumptions.template.json` 另存为自己的文件，填写参数，将 `confirmed` 改为 `true`，填写 `confirmed_by` 和判断依据。随后：

```bat
python run_finance.py research value --project "PROJECT" --company company_b --assumptions "我的估值参数.json"
```

重要输入规则：

- 百分比用小数，5% 填 `0.05`；金额全部为原币基本单位，不能把“亿元”数值当作“元”；股数用股。
- 所有基准身份、数据指纹和分析指纹来自模板，不自行拼接。
- 首版为完整财年末估值，估值日必须等于选定基准年财年末；不在期间中途套用整年现金流。桥接数据与参考股价也对应同一估值日。
- 只预填已审核收入等历史事实，不替用户推断 EBIT 利润率、长期增长率、WACC 或股数。
- 基准经营性非现金营运资本必须核实其组成，不直接用“流动资产减流动负债”替代。
- WACC 直接模式填 `mode: "direct"`、`wacc` 和 `rationale`。组成项模式填 `mode: "components"`，填写无风险利率、Beta、股权溢价、额外国家风险溢价、税前债务成本、债务税率、权益和债务市场价值以及依据，不再另外填写 WACC。
- 每个情景填写连续 1 至 15 年的增长、EBIT 利润率、现金税率、折旧摊销/收入、资本支出/收入和经营 NWC/收入。可以提交一至三个情景，名称限 Base、Bear、Bull；各情景使用相同预测年数。
- 终值填写长期增长、利润率、税率和 ROIC。代码按 `g/ROIC` 计算再投资率，不假定长期增长无需投资。要求 `WACC > g` 且 `ROIC > g`。
- 填写超额现金、非经营资产、有息债务、少数股东权益、优先股、其他请求权及稀释股数；即使某项没有，也由用户明确填 `0`。核实租赁和受限现金，避免重复调整。
- 参考股价可空。未提供时不计算相对价格差异。模型权益残值非正时，不输出可误读为负股价的每股模型价值。
- 敏感性网格由用户指定 WACC 与长期增长率列表；无效组合保留原因，不输出无穷大。

输出在邀请目录下独立的 `valuation_*` 文件夹：`assumptions.json`、`valuation.json` 和 `DCF估值.xlsx`。工作簿含预测现金流图、估值汇总、详细预测、终值和桥接、敏感性、用户参数、公式依据和条件性结论。新增比较和 DCF 工作簿展示代码算出的数值，公式登记于代码与“公式与依据”页；它们不会因用户在 Excel 中改一格而自动重建整个模型，需修改参数文件并重新运行代码。

## 公式及解释边界

```text
Ke = Rf + Beta × ERP + 额外国家风险溢价
WACC = Ke × E/(D+E) + Kd × (1−税盾税率) × D/(D+E)
EBIT = 收入 × 用户确认的 EBIT 利润率
现金税 = max(EBIT,0) × 现金税率
FCFF = EBIT − 现金税 + 折旧摊销 − 资本支出 − 经营NWC增加额
终值再投资率 = 长期增长率 / 长期ROIC
终值FCFF = 终值税后经营利润 × (1−终值再投资率)
终值 = 终值FCFF / (WACC−长期增长率)
经营资产价值 = 预测FCFF现值之和 + 终值现值
普通股权益价值 = 经营资产价值 + 超额现金 + 非经营资产 − 有息债务 − 少数股东权益 − 优先股 − 其他请求权
每股模型价值 = 正的普通股权益价值 / 稀释股数
```

负 EBIT 不假定即期抵税或结转亏损。当前用完整年度、年末折现、固定情景 WACC；债务成本和风险参数由用户确认。已有历史简化 FCF 不是 FCFF，不直接代入 DCF。系统说明终值依赖、负现金流、相对参考价格差异等条件，不把假设下的模型结果包装成确定的交易建议。

方法参考：[CFA Institute Free Cash Flow Valuation](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/free-cash-flow-valuation)；[Damodaran Excess Returns and Terminal Value](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/termvalueexreturns.htm)。
